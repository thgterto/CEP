## 2024-05-19 - V8 Optimization and GC in Statistical Functions
**Learning:** Using the spread operator (`[0, ...ranges]`) on very large arrays (e.g., 200k+ elements) inside hot paths like `computeIMR` can trigger a `RangeError: Maximum call stack size exceeded`. Additionally, mapping, slicing, and spreading data for statistical subgrouping (like in `computeXbarR`) causes excessive Garbage Collection pauses and significant execution time overhead.
**Action:** When working with massive numerical datasets in Node.js/V8, always replace array spreading, `.slice()`, and functional methods (`.map()`) with manually pre-allocated arrays (`new Array(len)`) and explicit single-pass `for` loops. This yields a massive performance multiplier (~6x to ~12x faster) and avoids edge-case stack overflows.
