
## 2026-05-15 - [V8 Array Optimization & Exponentiation Avoidance]
**Learning:** In Node.js v22/V8, when working with mathematical charts like EWMA that have loops matching the input array length `N`, allocating output arrays in advance using `new Array(len)` and managing indices manually is drastically faster than starting with `[mean]` or `[]` and repeatedly calling `.push()`. More importantly, repeatedly computing exponentiations that increase linearly with an index using `Math.pow(base, 2 * (i + 1))` inside hot statistical loops creates massive overhead. By replacing this with a running multiplication state (`currentPow *= base * base`), a >2.5x performance speedup was achieved (~1.12s down to ~416ms in benchmarks for 100k items) because it completely skips expensive floating-point math function calls.
**Action:** When calculating statistics that scale geometrically with sequence index, ALWAYS refactor `Math.pow()` inside `for` loops into a running multiplier (`currentPow *= factor`). Pair this with explicit pre-allocation via `new Array(size)` rather than `Array.prototype.push()`. Ensure exact matching of default values in initial/fallback states (like empty arrays) to avoid mathematical regressions (NaN != 0) when refactoring array initializations.
