## 2026-05-19 - Avoiding Committing Binary Artifacts During Refactoring
**Learning:** When running frontend verification scripts (like Playwright with `page.screenshot()`), large binary artifacts (e.g., `verification.png`) can be generated and accidentally staged or committed, cluttering version control.
**Action:** Always perform a workspace cleanup and check `git status` to ensure generated scratchpad scripts, logs, and binary files are explicitly removed before staging changes and submitting.
## 2026-05-19 - Safe Refactoring in EWMA
**Learning:** In Node.js v22, avoiding `Array.prototype.shift()` (an O(N) operation) and utilizing pre-allocated arrays along with hoisted loop-invariant math operations (like `1 - lambda`) inside hot statistical loops yields over 2x speedup on large datasets.
**Action:** When optimizing loop-heavy array manipulations in statistical algorithms (e.g. SPC), prioritize static allocation and scalar state-tracking (e.g., `prevZ`) over dynamic structural mutations (`push`, `shift`), while preserving native functions like `Math.pow` inside the loop to avoid floating point drift.
## 2024-05-24 - Optimization: Math.sign vs explicit ternary and one-pass variance
**Learning:** Native `Math.sign` performs adequately well, but caching array property access (like `data[i-1]` -> `prevValue`) yields measurable execution speedup without losing exact precision. Additionally, a single-pass computational formula for variance `(sumSq - n * mean^2) / (n - 1)` gives robust improvements (~20% faster) for algorithms like `computeXbarS` by halving inner loop iterations.
**Action:** When working on array-heavy loops in V8, prioritize eliminating redundant property accesses (by local caching) and reducing loop passes where computationally equivalent formulas exist.
## 2024-05-24 - Optimization Rejection: Catastrophic Cancellation in single-pass variance
**Learning:** While the naive single-pass computational formula `(sumSq - n * mean^2) / (n - 1)` is faster by reducing O(N) iterations, it is notoriously susceptible to catastrophic cancellation with floating point arithmetic (when variance is small relative to the mean, large numbers truncate significant digits in IEEE-754). This makes it mathematically unsafe for a Statistical Process Control (SPC) library.
**Action:** Do not use naive single-pass sum-of-squares formulas for variance. If variance needs to be optimized, either stick to the stable two-pass algorithm or use Welford's Algorithm. I will revert this change and choose a safer optimization, such as caching invariant variables or property access in loops.
