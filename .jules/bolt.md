## 2026-05-19 - Avoiding Committing Binary Artifacts During Refactoring
**Learning:** When running frontend verification scripts (like Playwright with `page.screenshot()`), large binary artifacts (e.g., `verification.png`) can be generated and accidentally staged or committed, cluttering version control.
**Action:** Always perform a workspace cleanup and check `git status` to ensure generated scratchpad scripts, logs, and binary files are explicitly removed before staging changes and submitting.
## 2026-05-19 - Safe Refactoring of Statistical Charts using Pre-allocated Arrays
**Learning:** When refactoring O(N) array transformations (like CUSUM, EWMA, IMR) to avoid dynamic arrays (`push`, `shift`, spread syntax) and use pre-allocated arrays, it is crucial to handle edge cases natively to avoid runtime exceptions (e.g. `RangeError: Invalid array length` with `new Array(len - 1)` when `len` is `0`). Using inline fallbacks inside the constructor (e.g. `new Array(len === 0 ? 1 : len)`) combined with explicit element initialization ensures strict logical and type equality without creating boundary errors. Re-using previously calculated statistical measures (e.g., passing `mu` into `stdDev`) also reduces total algorithm passes.
**Action:** Always pre-allocate arrays bounded by size checks (e.g., `Math.max(0, len)` or conditional defaults) when substituting dynamic arrays, and strictly enforce backward-compatibility against original edge-case outputs (empty arrays, singular values) using ad-hoc `assert.deepStrictEqual` scripts in isolated environments.
