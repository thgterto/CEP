## 2026-05-05 - Avoiding Array Iteration Overhead in Subgroup Processing
**Learning:** In V8 (Node.js v22), calculating statistical subgroups by heavily utilizing `Array.prototype.slice`, `Array.prototype.map`, and the spread operator (`...` e.g., `Math.max(...g)`) is a major performance bottleneck for Control Charts (Xbar-R, Xbar-S). It causes continuous memory allocation, Garbage Collection (GC) pressure, and risks `RangeError: Maximum call stack size exceeded` for large datasets.
**Action:** When grouping data, replace intermediate array methods with a single-pass `for` loop, using `Math.floor(len / n)` for bounds and initializing static arrays (`new Array(numGroups)`). Inline subgroup math directly in the loop to eliminate closure/function call overhead, achieving >3x to >5x speedups. Always ensure any negative length errors are avoided by guarding against zero sizes.
